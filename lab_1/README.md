# Лабораторна робота №1

## Реалізація та перевірка зворотного поширення похибки

## 1. Мета роботи

Мета роботи — реалізувати алгоритм зворотного поширення похибки для простої нейронної мережі без використання засобів автоматичного диференціювання, а потім перевірити правильність отриманих градієнтів за допомогою PyTorch та чисельного диференціювання.

У роботі необхідно:

* виконати прямий прохід нейронної мережі;
* самостійно реалізувати обчислення градієнтів;
* порівняти ручні градієнти з результатами PyTorch Autograd;
* виконати чисельну перевірку окремих градієнтів;
* провести експеримент із навмисною помилкою в реалізації;
* перевірити відтворюваність результатів.

## 2. Вихідні дані та підготовка

Для роботи використовується датасет Iris із бібліотеки `scikit-learn`.

Датасет містить:

* 150 об'єктів;
* 4 ознаки;
* 3 класи;
* по 50 об'єктів кожного класу.

Дані поділяються на навчальну та тестову вибірки у співвідношенні 70/30 зі збереженням пропорцій класів.

Для відтворюваності використовується генератор випадкових чисел:

```python
np.random.default_rng(0)
```

У навчальній вибірці міститься 105 об'єктів:

* клас 0 — 35;
* клас 1 — 35;
* клас 2 — 35.

У тестовій вибірці:

* клас 0 — 15;
* клас 1 — 15;
* клас 2 — 15.

Стандартизація ознак виконується лише за статистиками навчальної вибірки. Для кожної ознаки обчислюються середнє та стандартне відхилення, після чого виконується перетворення:

```text
X_scaled = (X - mean) / std
```

При цьому середнє та стандартне відхилення обчислюються для навчальної вибірки та потім застосовуються також до тестової.

Для стандартного відхилення використовується `ddof=0`.

## 3. Архітектура нейронної мережі

Використовується нейронна мережа:

```text
X → Linear(4, 8) → ReLU → Linear(8, 3)
```

Параметри мережі мають такі розмірності:

| Параметр | Розмірність |
| -------- | ----------- |
| W1       | (4, 8)      |
| b1       | (8,)        |
| W2       | (8, 3)      |
| b2       | (3,)        |

Для `W1` використовується ініціалізація He normal, для `W2` — Xavier normal. Вектори зміщення `b1` та `b2` ініціалізуються нулями.

Для ініціалізації параметрів використовується окремий генератор:

```python
rng_init = np.random.default_rng(0)
```

Спочатку генерується `W1`, після цього `W2`.

Усі обчислення виконуються у форматі `float64`.

---

## 4. Прямий прохід та функція втрат

Прямий прохід складається з двох лінійних перетворень та функції активації ReLU.

Спочатку обчислюється:

```text
Z1 = X · W1 + b1
```

Після цього застосовується ReLU:

```text
A1 = ReLU(Z1)
```

де:

```text
ReLU(z) = max(0, z)
```

Далі виконується друге лінійне перетворення:

```text
Z2 = A1 · W2 + b2
```

`Z2` містить логіти для трьох класів.

Для обчислення softmax використовується чисельно стабільна форма log-softmax. Перед експонуванням від кожного рядка віднімається його максимальне значення:

```text
log_probs = Z2 - max(Z2) - log(sum(exp(Z2 - max(Z2))))
```

Функція втрат — середня крос-ентропія по всіх навчальних об'єктах:

```text
L = -(1 / N) · sum(log_probs[i, y[i]])
```

де:

* `N` — кількість навчальних об'єктів;
* `y[i]` — правильний клас для об'єкта `i`.

Отримане значення втрат:

```text
Loss = 1.4562007801142816
```

## 5. Ручна реалізація зворотного проходу

Зворотний прохід реалізовано вручну без використання автоматичного диференціювання NumPy.

Спочатку обчислюється ймовірність класів:

```text
probs = exp(log_probs)
```

Градієнт за логітами для середньої крос-ентропії:

```text
dZ2 = probs
dZ2[i, y[i]] = dZ2[i, y[i]] - 1
dZ2 = dZ2 / N
```

Після цього обчислюються градієнти параметрів другого шару:

```text
dW2 = A1ᵀ · dZ2
```

```text
db2 = sum(dZ2, axis=0)
```

Градієнт за виходом ReLU:

```text
dA1 = dZ2 · W2ᵀ
```

Похідна ReLU визначається як:

```text
ReLU'(z) = 1, якщо z > 0
ReLU'(z) = 0, якщо z ≤ 0
```

Тому:

```text
dZ1 = dA1 · (Z1 > 0)
```

Для першого шару:

```text
dW1 = Xᵀ · dZ1
```

```text
db1 = sum(dZ1, axis=0)
```

Отримані розмірності градієнтів:

| Градієнт | Розмірність |
| -------- | ----------- |
| dW1      | (4, 8)      |
| db1      | (8,)        |
| dW2      | (8, 3)      |
| db2      | (3,)        |

Усі отримані градієнти є скінченними.

## 6. Звірка з PyTorch

Для перевірки правильності ручної реалізації створюється аналогічна модель у PyTorch.

Параметри NumPy-моделі передаються до PyTorch-моделі без зміни їх значень. Для порівняння використовується `CrossEntropyLoss`.

Отримані значення функції втрат:

| Реалізація |               Loss |
| ---------- | -----------------: |
| NumPy      | 1.4562007801142816 |
| PyTorch    | 1.4562007801142818 |

Невелика різниця виникає через особливості виконання операцій із числами з плаваючою крапкою.

Максимальні абсолютні різниці між ручними градієнтами та PyTorch:

| Параметр | Максимальна абсолютна різниця |
| -------- | ----------------------------: |
| W1       |         4.163336342344337e-17 |
| b1       |        3.2959746043559335e-17 |
| W2       |         5.551115123125783e-17 |
| b2       |         1.249000902703301e-16 |

Критерій перевірки:

```text
|a - b| ≤ 10⁻¹²
```

Усі градієнти успішно пройшли перевірку.

## 7. Чисельна перевірка окремих градієнтів

Для додаткової перевірки використовується центральна різниця.

Чисельний градієнт обчислюється за формулою:

```text
g_num = (L(θ + ε) - L(θ - ε)) / (2 · ε)
```

де:

```text
ε = 10⁻⁶
```

Перевіряються чотири параметри:

* `W1[0,0]`;
* `b1[0]`;
* `W2[0,0]`;
* `b2[0]`.

Результати:

| Параметр |       Чисельний |          Ручний |  Різниця |
| -------- | --------------: | --------------: | -------: |
| W1[0,0]  | -0.019920184391 | -0.019920184331 | 6.03e-11 |
| b1[0]    | -0.070566111621 | -0.070566111584 | 3.63e-11 |
| W2[0,0]  |  0.135230208698 |  0.135230208605 | 9.22e-11 |
| b2[0]    |  0.085521644988 |  0.085521644842 | 1.46e-10 |

Критерій перевірки:

```text
|g_num - g_manual| ≤ 10⁻⁷
```

Усі чотири градієнти відповідають критерію.

## 8. Дослід із навмисною помилкою

Для перевірки здатності тестів виявляти помилки було навмисно змінено реалізацію градієнта за логітами.

У правильній реалізації виконується ділення на кількість об'єктів:

```text
dZ2 = dZ2 / N
```

У помилковій версії цей крок видаляється.

При цьому сама функція втрат не змінюється, оскільки помилка внесена тільки у зворотний прохід.

Для `N = 105` неправильні градієнти стають приблизно у 105 разів більшими за правильні.

Результат порівняння з PyTorch:

| Перевірка | Результат |
| --------- | --------- |
| Loss      | True      |
| dW1       | False     |
| db1       | False     |
| dW2       | False     |
| db2       | False     |

Максимальні абсолютні різниці:

| Параметр | Максимальна різниця |
| -------- | ------------------: |
| W1       |   18.51813798075919 |
| b1       |  15.641093948478263 |
| W2       |  34.193432939632565 |
| b2       |  11.197086181821382 |

Чисельна перевірка також виявила помилку:

| Параметр |       Чисельний | Неправильний ручний |         Різниця |
| -------- | --------------: | ------------------: | --------------: |
| W1[0,0]  | -0.019920184391 |     -2.091619354708 |  2.071699170317 |
| b1[0]    | -0.070566111621 |     -7.409441716360 |  7.338875604739 |
| W2[0,0]  |  0.135230208698 |     14.199171903575 | 14.063949169488 |
| b2[0]    |  0.085521644988 |      8.979772708405 |  8.894251063417 |

Таким чином, експеримент показує, що однакове значення функції втрат ще не гарантує правильності реалізації зворотного проходу. Помилку в градієнтах виявляють як порівняння з PyTorch, так і чисельне диференціювання.

Після проведення експерименту правильну реалізацію з діленням на `N` було відновлено.

## 9. Висновки

У лабораторній роботі було реалізовано прямий та зворотний проходи для простої нейронної мережі з архітектурою:

```text
4 → 8 → 3
```

Прямий прохід включає два лінійні шари, функцію активації ReLU та чисельно стабільне обчислення log-softmax і крос-ентропії.

Зворотний прохід було реалізовано вручну за допомогою матричних операцій NumPy. Для кожного параметра мережі були отримані відповідні градієнти `dW1`, `db1`, `dW2` та `db2`.

Правильність реалізації підтверджено двома способами. По-перше, ручні градієнти практично збігаються з градієнтами PyTorch: максимальна абсолютна різниця для всіх параметрів не перевищує `1.25 · 10⁻¹⁶`, що значно менше встановленого порогу `10⁻¹²`. По-друге, окремі градієнти успішно пройшли перевірку чисельним диференціюванням.

Окремий експеримент із навмисним видаленням ділення градієнта за логітами на кількість об'єктів показав, що помилка у зворотному проході може не впливати на значення функції втрат, але суттєво змінювати градієнти. У цьому випадку всі перевірки градієнтів виявили помилку.

Таким чином, у роботі було не тільки реалізовано алгоритм зворотного поширення похибки, а й продемонстровано практичні способи перевірки правильності його реалізації.
